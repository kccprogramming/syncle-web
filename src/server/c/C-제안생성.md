# C: 회의 제안 생성

## 실행

저장소 루트, Node.js 22.18 이상에서:

```sh
node examples/proposal-demo.ts
node tests/proposals.test.ts
node tests/scheduling.test.ts
```

예시 데이터임을 콘솔과 결과의 `dataMode: "example"`로 표시한다.
실제 AI·장소 검색·로그인·DB 저장은 하지 않는다. 정적 타입 검사는 아직 수행하지 않았다.

## 입력 → 처리 → 출력

1. 호출자가 팀 ID, 제안 ID, 예시/실제 데이터 방식을 넘긴다.
2. 주입한 `extractConditions(teamId)`로 B의 조건을 받는다.
3. 시간 계산 함수를 호출한다.
4. 대면이고 시간 후보가 있으면 후보 시간마다 주입한 `findPlaces(request)`를 호출한다.
5. 목적·안건·근거·시간별 장소·경고를 `status: "draft"`인 제안으로 반환한다.

주입은 함수 이름과 입력·출력 약속만 정하고, 실제 동작 함수를 밖에서 전달하는 방식이다.
`examples/proposal-demo.ts`에서는 예시 함수를 전달한다. 팀원 코드가 오면 여기 연결을 실제 함수로 바꾼다.
B·D의 응답 형식이 다르면 변환 함수를 두고 맞춘다. 실제 팀의 계약은 아직 확인하지 않았다.

## 실패와 미확인

- B 실패: `CONDITIONS_FAILED` 예외. 원본 외부 오류는 노출하지 않는다.
- B 형식 오류/시간 입력 오류/다른 팀 데이터: `INVALID_CONDITIONS` 예외.
- D 실패 또는 잘못된 결과: 해당 시간의 `failed` 상태. 시간 후보와 다른 시간의 장소는 유지.
- D가 정상적으로 빈 배열 반환: `empty`. 조회 실패와 구분.
- 경로 누락: 해당 참여자의 `minutes: null`, `method: "unknown"`. 0분으로 표시하지 않는다.
- 온라인: `skipped_online`. 시간 후보 없음: `skipped_no_times`.
- 미응답/미확인 시간과 이동시간은 경고에 표시.

장소의 최대 이동시간·공평성 순위는 C가 임의로 생성하지 않는다. D 결과를 연결할 예정이다.
참석 인원은 현재 팀 전체 인원 기준이다. 일부 참석 후보의 최종 장소 검색 정책은 팀 합의가 필요하다.
예약 기능과 예약 가능 여부 확인은 범위에서 제외한다. D는 장소의 실제 사이트/상세 URL을 제공하고, C와 프런트는 링크 열기만 지원한다.

## 다음 연결 지점

- A: 로그인 사용자·팀 접근 확인, 제안 ID 생성, 저장과 채팅 카드 등록.
- B: 실제 조건 추출 함수를 임시 Conditions 계약으로 변환.
- D: 시간 후보별 장소 조회와 실제 경로 정보를 Place 계약으로 변환.
- 프런트: 반환한 시간·장소·안건과 상태·경고 표시.

아직 서버 API·투표·확정·DB 영속 저장을 구현하지 않았다.
클라이언트가 보내는 팀 ID만으로 권한을 인정하면 안 된다. 실제 API 연결 시 서버 인증과 팀 멤버십 검사가 필요하다.

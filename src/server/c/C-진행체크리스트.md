## 투표·확정 함수의 의미

`startProposalFlow`는 제안과 팀원/리더 목록을 받는다. 이 목록 자체를 인증하지 않는다.
`castVote`는 이전 상태를 바꾸지 않고 새 상태를 반환한다. 호출자가 새 상태를 보관해야 한다.
`voteSummary`는 투표자 수와 선택 수를 구분한다. 투표는 선호 표현이며 B의 가능 조건을 자동 변경하지 않는다.
`confirmProposal`은 확정 회의를 새 상태에 담는다. 실제 매장 예약이나 DB 저장은 아니다.
장소의 예약 상태는 취급하지 않는다. D가 제공하는 `url`로 사이트만 연다. 링크가 없으면 미제공 안내를 표시한다.
`upcomingMeetings`는 전달된 허용 팀 ID로만 필터링하므로 서버가 그 팀 목록을 결정해야 한다.

확정된 상태에서는 상태의 `status`가 `confirmed`이며, 내부 `proposal`은 생성 당시의 초안 스냅샷이다.
화면과 실제 API에서는 상태의 `status`를 사용한다. 실제 DB와 프런트 계약에 맞춰 연결 시 통일한다.

현재 함수 호출은 같은 프로세스의 메모리에서만 동작한다.
프로그램 종료·새로고침 후 유지, 여러 사용자 동시 작업, 실제 로그인은 아직 검증하지 않았다.

## 독립 확인 화면

`node tools/build-check-page.mjs <출력 HTML 경로>`로 TypeScript 모듈을 묶는다.
결과 HTML은 서버·Node 설치 없이 브라우저에서 열 수 있다. 외부 자원은 불러오지 않는다.
B·D의 실시간 호출 대신 예시 함수를 사용하며 시간 계산·투표·확정·.ics는 실제 C 함수를 실행한다.
이 확인 화면용 JavaScript는 전달 편의를 위한 빌드 결과이고, C 기능 원본 언어는 TypeScript다.
파일 미리보기는 스크립트를 차단할 수 있으므로 다운로드 후 브라우저로 열어야 한다.

수동 확인 순서:
1. 두 사람 응답 상태에서 후보 생성, 가능 인원 확인.
2. 팀원 1로 체크박스 선택 후 투표 저장. 팀원 2로 전환해 투표.
3. 팀원 2로 확정 시 권한 안내 확인.
4. 팀원 1로 전환 후 동그라미 후보 선택·확정.
5. .ics 내려받아 한국 시간과 제목 확인. 실제 예약은 아님.
6. 미응답 상황으로 새 제안을 만들고 확정 차단 확인.
7. 온라인 형식으로 새 제안을 만들고 장소 없이 확정 확인.

브라우저 검증: 관리형 Chromium에 HTML 내용을 직접 로드하여 후보 표시·투표·리더 권한·대면/온라인 확정·미응답 차단·입력 오류 검사를 통과했다.
이 환경은 file:// 탐색이 차단되어 다운로드 후 파일 열기는 지우 컴퓨터에서 확인해야 한다.
개발자용 `tools/browser-check.mjs`는 Playwright와 Chromium이 있는 환경에서만 실행한다. 일반 코드 테스트와 HTML 파일 실행에는 설치가 필요 없다.

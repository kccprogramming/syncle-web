# C: 시간 후보 계산 첫 버전

이 모듈은 AI·DB·프런트와 독립적이다. 팀 공통 앱이나 패키지 설정을 새로 만들지 않았다.
Node.js 22.18 이상(현재 검증 환경 24.22.1)의 TypeScript 직접 실행 기능을 사용한다.
팀의 실제 Next.js에 연결할 때는 팀 TypeScript 설정에 맞춰 import 경로를 조정할 수 있다.

저장소 루트에서 실행:

```sh
node tests/scheduling.test.ts
node examples/scheduling-demo.ts
```

## 입력 → 처리 → 출력

- 입력: 팀 ID, 검색 기간, 회의 길이, 참여자별 가능·불가 구간과 응답 상태.
- 처리: 시작 시각부터 기본 30분 간격으로 회의 전체 길이를 확인하고 인원 집계.
- 출력: 최대 3개 시간 후보, 후보별 가능·불가·미확인 사람, 필수 참석자 포함 여부.
- AI 역할: 이 함수에는 없다. B가 자연어를 정리한 결과를 나중에 입력으로 변환한다.

데이터 계약은 `src/features/scheduling/types.ts`, 실행 가능한 입력 예시는 `examples/scheduling-demo.ts`에 있다.
날짜는 초 00과 `+09:00`을 명시한다. 시간 구간은 시작 포함·종료 제외다.

## 임시 정책

- 가능 인원 → 필수 참석자 포함 → 빠른 시각으로 정렬.
- 우선순위 순으로 서로 겹치지 않는 후보를 선택한다. 따라서 유효 후보가 있어도 3개보다 적을 수 있다.
- 명시적 가능 시간 밖은 불가가 아니라 미확인이다.
- 미응답·확인 필요 상태, 후보 안에서 가능/불가가 충돌하는 사람은 가능 인원에서 제외한다.
- `requiredMembersSatisfied: false` 후보도 비교용으로 반환한다. 확정 허용을 의미하지 않는다.
- 검색 기간·후보 간격·회의 길이를 호출자가 지정한다. 현재 시각 이후 검색 여부도 호출자가 결정한다.
- 최소 한 명의 확인된 가능 인원이 있어야 후보를 반환한다.
- 입력 오류는 예외다. API 연결 시 공통 오류 응답으로 변환해야 한다.

## 아직 연결하지 않은 것

B의 실제 출력 변환, D의 장소, Supabase 저장·인증, 제안·투표·확정 API, 프런트 화면, 캘린더 파일.
현재는 예시 데이터로 시간 계산만 실행한다. TypeScript 정적 타입 검사는 팀 도구 설정 연결 후 별도로 수행해야 한다.
